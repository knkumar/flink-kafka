#### **Part 1: Auto-Reject Gatekeepers (Crucial First Step)**

If ANY of these boxes are checked, the paper is an automatic **Strong Reject** (<50), overriding the 100-point scale.

* [ ] Single workload used to make broad claims.


* [ ] Cherry-picked configurations.


* [ ] Vendor-provided settings utilized for one system but not for competing systems.


* [ ] No tuning methodology described.


* [ ] Conclusions drastically exceed the provided evidence.


* [ ] Results based on a single experimental run.

#### **Part 3: Red Flags to Note (Deduct points in relevant sections)**

* 
**Moderate Issues:** Missing resource utilization metrics, small-scale experiments only, lack of robustness testing, or incomplete workload diversity.


* 
**Minor Issues:** Missing confidence intervals, limited discussion of edge cases, or omitted reproducibility details.



---

#### **Part 4: Final Meta-Review Calibration**

*Before assigning your final score, ensure you can answer **YES** to the following questions for any paper scoring above 80:*

* [ ] Did the paper reveal something that practitioners genuinely did not know before? 


* [ ] Would a system designer change decisions based on these results? 


* [ ] Are conclusions supported by enough evidence? 


* [ ] Is the benchmark fair enough that competing vendors would accept the results? 


* [ ] Could another research group reproduce the study? 


* [ ] Did the paper uncover architectural tradeoffs rather than simply reporting performance numbers? 


* [ ] Would the community reference this study when discussing these systems in the future?
