- 2026-07-17T09:56:00-07:00 [TOOL] Two independent bugs in `scripts/run-flink-w1-latency.sh` were silently corrupting or failing every long-duration/windowed Flink run: (1) `experiments/flink_w1/checkpoints/` is a host bind mount that survives `docker compose down -v`, so it accumulates checkpoints across every unrelated invocation ever run, and `FlinkIdentityJob.java` auto-resumes from the single highest-numbered `chk-N` across ALL of them with no topology-compatibility check, crashing the job at startup if that checkpoint belongs to a different workload (this killed the Flink W3/W4 30-min stability runs and both W3 checkpoint-interval tuning runs, `actual_count: 0` in every case); (2) `--timeout-sec` is an idle timeout on the Kafka console consumer, hardcoded at 180s in this script (unlike the Kafka Streams equivalent, which scales as `EVENTS/RATE_PER_SEC + 120`), so any run with a long silent period before output (every 30-minute windowed stability run) would idle out regardless of bug (1). Both fixed: clear the checkpoints dir at the start of every invocation, and scale the timeout the same way the Kafka Streams script does. The already-accepted Flink W1/W2 stability numbers are unaffected (they got lucky: the leftover checkpoint they stumbled on was incomplete, so Flink logged "No checkpoint found" and started clean), but don't trust any pre-fix Flink W3/W4/tuning result.
